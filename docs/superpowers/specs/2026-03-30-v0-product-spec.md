# V0 产品需求文档 — AI Trading Research Copilot

> 状态：Draft v2
> 日期：2026-03-30

## 1. 产品定义

**一个给个人交易者用的 AI 研究助手。不下单，只负责生成、保存、验证和复盘交易假设。**

核心价值：让每一次分析都留下痕迹，让每一个判断都能被事后验证，让交易决策越来越有据可依。

## 2. 用户画像

- 兼职交易者，每天花 30 分钟看盘
- 交易品种：BTC/ETH（加密）、A 股、美股
- 当前痛点：
  - 每次分析完就丢了，下次想不起来上次怎么判断的
  - 不知道自己哪类分析准、哪类不准
  - 改了分析策略不知道是变好还是变差
  - 条件单（"如果跌到 X 就做多"）没有跟踪机制，经常错过或忘记

## 3. 核心功能

### F1：今日分析（生成信号）

**用户故事：** 我想说"分析 BTC"就能得到一份结构化的交易计划，并自动保存。

**输入：** 品种名称（如 BTCUSDT）

**输出：**

- 结构化信号卡片：方向（做多/做空/观望）、置信度、入场价、止损、目标位
- 人可读分析报告：市场结构判断、关键位、背离、Playbook 匹配理由
- 自动归档（追加，不覆盖历史）

**关键规则：**

- 每次分析自动记录"快照"：用了什么分析模板版本、什么模型、什么时间段的数据。目的是事后能复现。
- 观望（watch）信号必须带条件：「如果价格跌破 X 则做多」，否则没有验证依据。

### F2：信号档案（查看历史）

**用户故事：** 我想查看过去的分析记录，看看当时怎么判断的、后来走势如何。

**输入：** "查看 BTC 最近 5 次分析" / "上次 ETH 做空结果怎样"

**输出：**

- 信号列表：时间、方向、入场价、当前状态
- 每个信号的事后验证：条件是否触发 → 止损/T1/T2 是否命中 → 最终盈亏

**关键规则：**

- 信号完整数据（snapshot）是唯一真相，索引只是查询加速层，可从 snapshot 重建。
- 报告（report.md）是核心产物，不是附属品，归档时必须同时保存。

### F3：复盘统计

**用户故事：** 我想知道"做空胜率如何"、"trend-pullback 这个策略靠不靠谱"。

**输入：** "做空胜率" / "按 playbook 统计" / "最近一个月表现"

**输出：** 分组统计表

- 按信号类型：即时单命中率、条件单触发率+触发后命中率
- 按 playbook：每种策略的胜率和盈亏比
- 按市场状态：趋势行情 vs 震荡行情的表现差异
- 观望占比：过高说明模型太保守

**关键规则：**

- 即时单（long/short）和条件单（watch）必须分开统计，不混分母。
- 版本对比时，同类型信号只跟同类型比。

### F4：策略迭代验证

**用户故事：** 我改了分析模板，想知道改了之后是变好还是变差。

**输入：** "跑一下新旧版本对比"

**输出：**

- 新版 vs 旧版的主指标对比（命中率、盈亏比）
- 明确结论：改进 / 退化 / 无显著差异

**关键规则：**

- 使用冻结的测试集（前 30 条信号）做对比，不受新增信号影响。
- 只看主指标（命中率/盈亏比），报告质量评分仅作参考。

### F5：消息通知（闭环跟踪）

**用户故事：** 我设了条件单"如果 BTC 跌到 60000 就做多"，我希望条件满足时能收到通知，而不是自己一直盯盘。

**场景覆盖：**

| 通知场景 | 触发条件 | 通知内容 |
|----------|----------|----------|
| 条件单触发 | 价格触达 conditional_entry | "BTC 已触达 60000，你在 03-28 的做多条件单已触发" |
| 止损预警 | 持仓信号价格接近 stop_loss（距离 < 1 ATR） | "BTC 距离止损位 59200 仅剩 0.8%，注意风险" |
| 目标到达 | 价格触达 T1/T2 | "BTC 已到达 T1 目标位 62000，可考虑部分止盈" |
| 信号失效 | 信号发出超过 N 天未触发条件 | "ETH 03-25 的条件单已超过 5 天未触发，建议重新评估" |
| 定时复盘提醒 | 每周日 | "本周共生成 8 条信号，即时单命中率 50%，点击查看复盘" |

**通知渠道（按优先级）：**

1. 飞书机器人（已有飞书生态，最快实现）
2. Telegram Bot（加密交易圈常用）
3. 邮件（兜底）

**关键规则：**

- 通知必须带上原始信号的关键信息（方向、入场、止损、目标），用户不需要打开系统就能做判断。
- 条件单触发通知是核心——这是从"分析"到"执行"的关键闭环。没有这个，watch 信号就是废纸。
- 价格监控需要后台定时检查（不要求实时，5 分钟级别即可）。

## 4. 用户流程

### 完整闭环

```text
分析 → 归档 → 监控 → 通知 → 执行（用户手动） → 验证 → 复盘
 F1      F1     F5     F5      用户自行下单       F2      F3
```

### 日常使用场景

**早盘（5 分钟）：**

```text
用户："分析 BTC"
系统：输出信号卡片 + 报告，自动归档
      → 如果 decision=watch，开始监控条件价位
```

**盘中（被动接收）：**

```text
系统：[飞书通知] BTC 已触达 60000，你在 03-28 的做多条件单已触发
用户：打开交易所，手动下单
```

**周末（10 分钟）：**

```text
系统：[定时提醒] 本周复盘
用户："按 playbook 统计本周"
系统：输出分组统计表
用户：发现 range-breakout 策略命中率很低 → 决定下周暂停使用
```

**月度迭代：**

```text
用户：修改了分析模板
用户："跑一下新旧版本对比"
系统：冻结测试集回归 → "新版即时单命中率 45% vs 旧版 38%，改进"
用户：确认上线新版
```

## 5. 成功指标

### 产品指标（这个工具有没有用）

| 指标 | 定义 | 目标 |
|------|------|------|
| 日活跃使用 | 每天至少生成 1 条信号 | 连续使用 > 4 周 |
| 信号积累 | 总信号数 | 第一个月 > 30 条 |
| 复盘频率 | 每周至少查看 1 次统计 | 每周 > 1 次 |
| 通知响应率 | 收到条件单通知后 30 分钟内有操作的比例 | > 60% |

### 交易质量指标（分析准不准）

**即时单（long/short）：**

| 指标 | 定义 | 目标 |
|------|------|------|
| 命中率 | T1 命中 / 即时单总数 | > 40% |
| 盈亏比 | 平均盈利 / 平均亏损 | > 1.5:1 |

**条件单（watch）：**

| 指标 | 定义 | 目标 |
|------|------|------|
| 触发率 | 条件满足 / 条件单总数 | 仅观测 |
| 触发后命中率 | 触发后 T1 命中 / 已触发数 | 样本量够后设目标 |
| 观望占比 | watch / 全部信号 | 仅观测（过高 = 太保守） |

**指标层级规则：**

1. 第一层：交易结果（命中率、盈亏比）— 唯一优化目标
2. 第二层：过程诊断（结构判断准确率、关键位有效性）— 找原因用
3. 第三层：报告质量（LLM 评分）— 仅参考，不做优化方向

**如果质量评分提升但命中率下降，回滚。**

## 6. V0 范围边界

### 做

| 功能 | 优先级 |
|------|--------|
| F1 今日分析（信号生成 + 自动归档） | P0 |
| F2 信号档案（历史查看 + 事后验证） | P0 |
| F3 复盘统计（分组统计 + 命中率） | P0 |
| F4 策略迭代验证（冻结测试集回归） | P1 |
| F5 条件单触发通知 | P1 |
| F5 止损/目标到达通知 | P2 |
| F5 定时复盘提醒 | P2 |

### 不做（V0 明确排除）

| 排除项 | 原因 |
|--------|------|
| 自动下单 | 风险不可控，V0 只辅助决策 |
| Web Dashboard | 先用 CLI 验证价值，避免过早投入 UI |
| Agent 自主决策 | 先跑固定 workflow，证明不够再上 Agent |
| RAG 历史检索 | 信号量 < 50 条时向量检索没意义 |
| 多用户 | 自己用，不需要认证和权限 |

### 延后决策

| 决策 | 触发条件 | 信号 |
|------|----------|------|
| 固定 workflow → Agent | 记录到 3+ 个场景"workflow 不够用" | V0 日常使用中积累证据 |
| 加 RAG | 信号量 > 50 | 向量检索有统计意义 |
| 加 Dashboard | 明确知道要看什么图表 | CLI 复盘统计中自然浮现 |
| Python → TypeScript | 评估 Mastra 的 ROI | V0 跑通后决定 |

## 7. 风险

| 风险 | 缓解 |
|------|------|
| 信号太少无法统计 | 先积累 30+ 条再做统计报告 |
| 改模板导致质量下降 | F4 回归测试，改前必跑对比 |
| 条件单没通知 = 废纸 | F5 条件单通知列为 P1 |
| 评估被 LLM 评分牵偏 | 主指标（命中率）永远优先 |
| 回归口径随信号增长漂移 | 冻结前 30 条信号为固定测试集 |
| 过早引入复杂技术 | V0 先固定 workflow，延后 Agent/RAG/Dashboard |

## 8. 开放问题

- [ ] 通知渠道优先用飞书还是 Telegram？取决于日常哪个 app 更常看
- [ ] 价格监控的数据源：复用现有 MCP K 线接口，还是单独做一个轻量价格轮询？
- [ ] 信号失效的时间阈值：条件单超过几天未触发算失效？暂定 5 天，使用中调整
- [ ] 止损预警的距离阈值：距离 stop_loss 多近开始告警？暂定 1 ATR，使用中调整
