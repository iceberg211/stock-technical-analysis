# 输出约定

## 原则

用户先要看懂“现在是什么盘、该怎么做”，不是先看数据字典或内部判断表。

默认阅读顺序：

```text
先给结论
→ 用价格事实说明为什么
→ 给出条件式计划 / 等待 / 不交易
```

完整报告仍可保留栏目，但栏目是阅读辅助，不是填空模板。禁止：

- 把基础信息写成超长清单；
- 单独开“作者式二元决策”或课程章节编号这类生硬标题；
- 先喊偏多偏空，再补理由；
- 把内部状态机字段原样甩给用户。

## 输出分级

| 模式 | 场景 | 输出 |
|---|---|---|
| 完整模式 | 首次分析、状态重建、用户要求完整报告 | 简短结论 + 必要证据 + 交易计划 |
| 盘中精简模式 | 新 K 线更新、追问“现在呢” | 只说变化、当前动作、下一触发 |
| 快问快答 | 单个概念或价位问题 | 直接结论、证据范围、缺失条件 |

“测试”“完整分析”“复核”默认使用完整模式。只有用户明确要求简短、盘中更新或只看结论时，才使用精简模式。完整模式应完整交代证据链，但不复制原始行情 JSON。

## 完整模式

优先用自然段落，不要机械堆叠小标题。若保留栏目，按下面约束写。

### 1. 先给结论

开头 3～6 行直接说清：

- 当前更像什么环境；
- Always In 是多、空还是不清楚；
- 当前最佳动作：做多 / 做空 / 等待 / 管理 / 不交易；
- 一句话原因。

示例口吻：

```text
现在更像失败突破后的交易区间，Always In 不清楚，短线略偏空。
现价位置一般，不追多也不追空，等待区间边缘确认。
```

### 2. 基础信息

只保留理解结论所必需的字段，默认 4～6 行：

- 品种
- 周期角色：背景 / 主判断 / 触发
- 分析时点与最后完整K线
- 数据来源
- 只有异常时才写：数据降级、缺周期、未完成K线、来源回退原因

不要默认输出：

- 请求/实际/分析根数的完整工程明细
- provider 内部参数堆砌
- 与结论无关的通道说明

需要审计数据质量时，再在文末用一行“数据备注”补充。

首次测试或完整复核时，基础信息必须增加一张紧凑数据表，至少包含：

```text
标的 / 数据源 / 分析时点 / 交易时段 / 复权口径
周期 / 实际K线数量 / 覆盖范围 / 最后完整K线 / forming或剔除记录
```

每个周期只列最后一根完整 K 线和最近必要的 6～12 根事实摘要，不列出全部原始 K 线。

### 3. 市场结构

用一张短表或两三段话说明多周期，不把每个格子都写成论文。

每个相关周期只回答：

- 最近发生了什么；
- 当前环境；
- Always In；
- 位置；
- 什么会推翻它。
- 仍然合理的备选解释，以及切换所需的价格事实。

高周期是背景，不是机械否决。低周期可以在高周期区间里形成局部趋势，也可以在高周期趋势里形成回调。

多标的完整报告必须逐标的完成上述结构，不得把三只股票合并成一段总判断。

### 4. 关键价位

只写会影响当前决策的位置：

- 最近支撑
- 最近阻力
- 当前位置意义
- 前方空间是否足够

每个价位用一句话说明“到这里后看延续还是失败”，不要把所有历史高低点都列出来。

### 5. 价格行为

这是完整报告的核心，用连续叙述，不要拆成生硬检查表。

至少覆盖：

1. 最近两到三个推动/回调；
2. 有没有关键突破、收盘是否在外侧、有没有跟进；
3. 多头在交易什么，空头在交易什么；
4. 哪一方现在更容易赚钱；
5. 最强反对证据是什么。

可以把“环境判断”自然写进这段，例如：

```text
从强反弹变成失败上破后的区间，是因为……
```

不要单独开：

- 作者式二元决策
- 课程章节编号
- 内部路由过程

### 6. 形态 / 模式

只写当前真正相关的一个主模式，最多一个备选：

- 主模式是什么；
- 为什么适用；
- 还缺什么；
- 常见误读是什么。

H1/H2/L1/L2、BLSHS、MTR、高潮反转都只能挂在环境下面，不能脱离环境单独成立。Open Reversal 是时段修正，Bailout 是持仓管理。

### 7. 综合研判

用 3～5 句话收束：

- 当前最佳动作；
- 核心逻辑；
- 主要解释、备选解释和切换条件；
- 什么会证明判断错误；
- 下一根或下一段需要看什么。

### 8. 交易决策卡

有交易方案、候选方案或明确“不交易”时使用。保持短而可执行：

```text
交易决策卡
- 动作：
- 主模式：
- 状态：candidate / armed / triggered / managing / invalidated / closed / none
- 持仓方式：scalp / swing / mixed / no_trade
- 订单方式：market / close / stop / limit / wait
- 触发：
- 初始风险：
- 止损逻辑：
- 逻辑风险：
- 目标空间：
- 目标：
- 失效：
- 不交易条件：
- 交易者方程：相对高/普通/相对低概率；空间与风险是否匹配
```

未要求仓位时写“仓位未计算”。需要账户仓位时再调用 `$trade-risk`。

用户已有仓位时，决策卡优先回答：

- 原前提成立 / 减弱 / 失效；
- 继续持有、减仓、退出或重进条件。

## 盘中精简模式

不要重复完整报告，也不要只写“状态不变”：

```text
盘中更新
- 新K线做了什么
- 这改变了什么 / 没改变什么（无实质变化也要说明）
- 主要解释、备选解释或切换条件是否变化
- 持仓方式或订单方式是否变化
- 当前动作
- 下一触发与失效
```

未完成K线不得确认新环境、MTR、高潮反转或 Always In 切换。已经准备好的止损订单可由可靠实时报价触发。普通重叠K线要说明它为什么没有改变主要结构、Always In 或当前动作。

盘中更新只使用 `data-budget.md` 规定的增量窗口；首次快照和重新回填时，先输出数据质量变化，再输出价格行为差量。

## 写作约束

- 先事实，后标签。
- 先环境，后形态。
- 先位置，后方向口号。
- 能用一段话说清时，不要拆成五张表。
- 数据异常只在影响结论时强调。
- 不输出伪精确胜率。
- 不把内部字段如 `primary_state`、`setup.status` 直接当作用户正文标题。

## 声明

每个含交易计划的回答末尾附上：

`以上分析仅供学习和参考，不构成投资建议。交易有风险，请基于自身判断做出决策，并自行承担所有风险。`
